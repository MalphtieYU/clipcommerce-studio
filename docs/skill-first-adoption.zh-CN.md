# 以 Skill 为主的安全使用方式

ClipCommerce 的 Skill 是对本地工作台的可选增强，而不是要求每个部门上传数据、改造流程或使用同一套工作台。工作台继续保存已有的结构化记录；只有团队主动生成协作数据包时，Skill 才会参考其中精简后的已授权数据。

## 它能帮助什么

`adaptive-work-improvement` Skill 可以让现有智能体：

- 理解部门当前目标、已授权信息、任务和约束；
- 区分已知事实、证据不足和可测试假设；
- 给出不超过三条小而可逆的改进建议；
- 在用户主动提供结果后，复盘一次建议是否有效，并总结一条待确认经验；
- 根据不同团队的实际工作适配，不要求所有人使用统一指标、表单或流程。

它不会后台运行、静默收集信息、修改其他项目、替换既有智能体、覆盖提示词或声称“自动学习了其他团队”。持续优化指的是：**用户授权的信息 → 建议 → 用户确认的小范围试验 → 用户提供结果 → 经人工确认的经验**。

## 从 GitHub 获取

```powershell
git clone https://github.com/MalphtieYU/clipcommerce-studio.git
```

在支持 Codex 插件/Skill 的智能体中，添加或指向这个目录：

```text
clipcommerce-studio/plugins/clipcommerce-analyst
```

核心 Skill 位于：

```text
plugins/clipcommerce-analyst/skills/adaptive-work-improvement
```

请保留该智能体原有的 system prompt、已有 Skill、项目配置与工作流；仅把本 Skill 作为新增的可选能力。不同工具的安装方式不同，应使用该工具原本的插件配置方式，不要通过覆盖配置来安装。

## 可直接交给智能体的提示词

```text
请从 GitHub 获取并使用 ClipCommerce 的 $adaptive-work-improvement Skill：
https://github.com/MalphtieYU/clipcommerce-studio

这是一个可选的改进层，不是新的主控流程。请不要改变、打断、替换或重新配置我现有的智能体、项目、文件、提示词、任务计划、工具、权限、环境变量、数据库和外部系统。默认只使用 Observe（观察）模式；任何实际改动都必须等待我在当前对话中明确确认。

我的当前目标： [填写]
当前正在运行且必须保持稳定的工作/项目： [填写；不知道可写“未提供”]
你已获授权使用的信息： [填写；未提供则仅限当前对话]
约束与隐私要求： [填写；未提供则所有建议保持只读和人工确认]

请先反馈：
1. 你理解到的目标、范围与现有工作；
2. 可用证据与关键未知项；
3. 已有工作中有证据支持的优点；
4. 最小且可逆的改进机会（最多三条），并区分事实、假设与需要验证的内容；
5. 每条建议如何保证不影响现有智能体、项目和流程；
6. 在我确认前，你不会做哪些改动。

不要因为 Skill 已有模板就要求我上传数据、填写工作台或改造流程；只有这些信息确实能解决当前问题时，才说明最小需要补充什么。不要编造资料、数据或业务规则。
```

## 何时才进入“学习”

只有当团队主动提供一次试验后的结果时，才要求智能体使用 Learn（学习）模式。它应比较“原本想验证什么”和“实际观察到什么”，并给出一条简短的待确认经验。是否写入团队文档、原有提示词或可选本地工作台，由人工决定。
